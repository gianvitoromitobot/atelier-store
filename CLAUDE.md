# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

@AGENTS.md

## Stack

Next.js 16 (App Router, `src/` dir, Turbopack) · TypeScript · Tailwind CSS v4 · Better Auth · Drizzle ORM · Neon Postgres (HTTP driver).

`next.config.ts` enables `cacheComponents` + `partialPrefetching`: data fetching is dynamic by default and anything reading runtime APIs (`headers()`, `cookies()`, auth session, uncached DB queries) must sit inside a `<Suspense>` boundary or the build reports a blocking route. Opt into caching with `"use cache"`. Do not add `runtime` route segment exports.

## Commands

Package manager is **pnpm** (pinned via `packageManager` in package.json; enable with `corepack enable pnpm`). Don't use npm or yarn. Dependency install scripts are blocked unless allowed in `pnpm-workspace.yaml` → `allowBuilds` (approve with `pnpm approve-builds <pkg>`).

```bash
pnpm dev         # dev server on http://localhost:3000
pnpm build       # production build (needs DATABASE_URL set; src/db throws without it)
pnpm lint        # eslint
pnpm typecheck   # next typegen + tsc --noEmit (LayoutProps/PageProps are generated globals)

pnpm db:generate # create SQL migration in drizzle/ from schema changes
pnpm db:migrate  # apply migrations to the DATABASE_URL database
pnpm db:push     # push schema directly (prototyping only)
pnpm db:seed     # upsert the catalogue from src/db/seed-data.ts (idempotent; reads .env.local)
pnpm db:studio   # Drizzle Studio
```

There is no test runner set up yet.

## Environment

Copy `.env.example` to `.env.local`. `drizzle.config.ts` loads `.env.local` explicitly via dotenv; Next.js loads it automatically. Better Auth reads `BETTER_AUTH_SECRET` / `BETTER_AUTH_URL` from the environment implicitly.

## Architecture

- `src/db/index.ts` — single Drizzle client (`db`) over `@neondatabase/serverless` HTTP. `db` and `src/lib/auth.ts` import `server-only`, so client components must never import them. The neon-http driver **does not support `db.transaction()`** (it throws); use `db.batch([...])` for atomic multi-statement writes, or switch to the `drizzle-orm/neon-serverless` (WebSocket `Pool`) driver if interactive transactions are needed (e.g. order creation + stock decrement).
- `src/db/schema/` — `auth.ts` holds the Better Auth core tables (`user`, `session`, `account`, `verification`); `store.ts` holds commerce tables. Everything is re-exported from `schema/index.ts`, which is what both drizzle-kit and the Better Auth adapter consume — new schema files must be re-exported there.
- `src/lib/products.ts` — catalogue data layer (see conventions below).
- `src/lib/auth.ts` — server Better Auth instance (Drizzle adapter, email+password). `nextCookies()` must remain the last plugin. Server-side session: `auth.api.getSession({ headers: await headers() })`.
- `src/lib/auth-client.ts` — browser client (`signIn`, `signUp`, `signOut`, `useSession`) for client components.
- `src/app/api/auth/[...all]/route.ts` — mounts all Better Auth endpoints under `/api/auth/*`.

Schema columns are declared with explicit snake_case names (`text("user_id")`); follow that pattern. Migrations in `drizzle/` are generated by `db:generate` and committed — don't hand-edit them.

When adding Better Auth plugins that need DB changes, regenerate the auth schema (`npx @better-auth/cli generate --output src/db/schema/auth.ts`), then `pnpm db:generate`.

UI work must follow `docs/design-system.md`: semantic colour tokens only (Tailwind's default palette is removed), type roles (`text-ui`, `text-body`, `eyebrow`…), and the primitives in `src/components/ui` (`Container`, `Section`, `Grid`, `Media`, `Button`/`ButtonLink`, `TextLink`). Tokens live in `src/app/globals.css`. `docs/design-reference.md` holds the visual research — inspiration only, never copy another brand's logo, fonts, imagery or copy.

Money is stored as integer minor units (`priceCents`) plus a `currency` code — keep it that way.

### Catalogue database conventions

- Postgres is the source of truth for products, categories and stock. Never reintroduce hardcoded product data in components or `src/lib/catalog.ts`; that file holds only view types, `stockState`, editorial content and curated homepage slug lists.
- Query the catalogue only through `src/lib/products.ts`. Each function uses `"use cache"` + `cacheTag(CATALOG_TAG)`, filters `active = true`, takes plain serializable arguments (slugs, not row objects), and maps rows to the `CatalogProduct` / `ProductDetail` view types — components don't consume Drizzle rows directly. After any catalogue write, call `revalidateTag(CATALOG_TAG)` (or `updateTag` in a Server Function).
- Model: `category 1──< product` via `product.category_id` (`onDelete: "restrict"`). Index foreign keys explicitly; guard invariants with `check()` constraints (`stock >= 0`, `price_cents >= 0`).
- Stock is an integer column on `product` while there are no variants; it moves to a variant table when variants are introduced. One image per product (`image_url` + `image_alt`) until a `product_image` table is needed.
- Seed data lives in `src/db/seed-data.ts`; `pnpm db:seed` upserts by slug and must stay idempotent. `src/db/seed.ts` builds its own client (it can't import `server-only` `src/db/index.ts`) and uses relative imports, not `@/`.
- `pnpm build` needs a migrated **and seeded** database: under Cache Components `generateStaticParams` must return at least one slug.
